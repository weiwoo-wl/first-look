# First Look 唱片店式作品展示与媒体上传

## 目标
把首页从普通信息流改为独立唱片店式陈列。作品像唱片封套，选择作品像选歌；图片和视频都能真实上传、展示和播放。首阶段只完成上传、陈列、详情与播放，不扩展评论、账号管理或推荐算法。

## 发布流程
已注册用户可为一个作品上传最多 8 个媒体文件，可混合图片与视频。图片单文件上限 10MB，视频单文件上限 200MB。第一项默认封面，用户可调整顺序。发布表单先创建待发布作品和媒体上传授权，浏览器直接上传到 Cloudflare R2，全部成功后提交媒体清单并发布；任一步失败都不展示不完整作品，用户可重试。

服务端校验登录、文件数量、声明类型、大小、作品归属和对象键。对象键由服务端生成，不允许客户端指定任意路径。下载通过本站媒体路由提供，设置正确 Content-Type、范围请求、缓存和安全响应头。只接受 JPEG、PNG、WebP、GIF、MP4、WebM、QuickTime；文件名不参与对象路径。未完成对象与孤儿对象后续可清理。

## 页面体验
首页使用响应式唱片墙。卡片主体为正方形封套，第一张图片为静态封面；视频封面显示播放标识，桌面悬停时静音预览，移动端不自动播放。卡片展示作品标题、创作者、类型和一句话介绍。点击封套进入 `/work/[slug]`。

详情页像抽出唱片：桌面左侧为大幅媒体舞台，右侧为标题、创作者、简介、创作故事、状态和体验链接；移动端上下排列。媒体可前后切换，视频提供原生播放控制、不会自动有声播放。缺失媒体时使用项目当前的柔和色块占位。

## 数据与接口
新增 `creation_media` 表：id、creation_id、object_key、media_type、mime_type、size、sort_order、created_at。作品增加可选体验链接。上传初始化接口返回每个文件的上传地址与对象键；完成接口核对对象存在后一次性写入媒体记录并将作品设为 published。首页与详情 API 返回媒体列表。

## 验证
验证混合媒体、8 个上限、超限大小、伪造类型、未登录上传、跨用户完成上传、部分失败、视频范围播放、移动端布局和首页到详情导航。构建通过后部署，使用真实图片和短视频走完发布到播放全链路。

## 基础设施
使用项目专用 Cloudflare R2 bucket，Worker 绑定名 `MEDIA`。不把 R2 凭证暴露给浏览器；若当前框架无法可靠生成原生预签名，则使用受登录保护的分片/流式 Worker 上传接口作为兼容实现，并保持同样的数据与权限边界。
