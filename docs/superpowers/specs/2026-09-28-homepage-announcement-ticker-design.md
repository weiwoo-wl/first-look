# 首页公告跑马灯设计

## 目标

在首页 slogan 与分类按钮之间增加一条紧凑、连续向左滚动的公告带。公告由站长或管理员发布和维护，避免首页新增独立大区块或明显增加首屏高度。

## 方案

- 在首页现有 hero 与分类筛选之间放置一行公告带：左侧固定“公告”标识，右侧内容连续向左循环；多条已发布公告以清晰分隔符连接。
- 公告文本可选附一个 HTTP(S) 链接；有链接时该条可打开链接，没有链接时仅展示文本。
- 鼠标悬停、键盘聚焦时暂停滚动；遵从系统减少动态效果设置，并提供可访问的暂停/继续控件。窄屏保持单行、可读，不增加独立导航行。
- 后台管理沿用现有站长／管理员认证：新增公告管理入口，可创建、编辑、发布、下架公告。公告包含短标题、内容、可选链接与状态；不加入定时发布、分类或互动。
- 将公告存入 D1；公开读取接口只返回已发布公告。所有写操作校验管理员身份、同源请求，并验证文本长度与链接协议。

## 数据与请求流程

新增公告表保存公告 ID、标题、内容、可选 URL、状态、创建/更新时间及操作者。首页读取公开接口并显示已发布内容；管理后台通过受保护的管理接口读取与修改全部公告。数据库不可用或公告列表为空时，不渲染公告条，也不影响首页其他内容。

## 验证

- 验证首页在桌面和窄屏下保持紧凑，滚动内容无空档，鼠标/键盘暂停可用，减少动态效果时不自动滚动。
- 验证访客可以读取已发布公告但不能写入；非管理员写操作被拒绝；管理员可创建、编辑、发布和下架。
- 执行项目生产构建；检查空列表、失效链接和数据库暂不可用时的首页状态。

## 范围外

不新增独立公告详情页、订阅通知、定时发布、多语言、评论或点赞功能。
