# First Look 公开试用基础完善设计

## 目标

在不改变 First Look 品牌、Slogan 和唱片式产品陈列的前提下，完善普通用户首次访问、注册登录、找回密码和发布作品的基础体验，并消除首页中容易误导用户的无效入口与历史代码。

本轮完成后，陌生用户应当能够理解如何注册、如何登录、如何找回密码；未登录用户进入发布流程时不会先填写一整页表单；首页各导航选项会真正影响产品列表。

## 范围

本轮包含：

- 标准化登录、注册和找回密码流程。
- 增加可访问的《用户协议》和《隐私政策》页面。
- 在进入发布页时检查登录状态，并保留登录后的返回地址。
- 让“今日精选、热门、最新、即将发布”产生真实的数据排序或筛选结果。
- 为加载中、没有数据和加载失败提供明确状态。
- 删除首页入口文件中不可执行的旧代码，以及确认没有被引用的旧版首页组件。
- 验证桌面端和移动端关键路径，并执行代码检查和正式构建。

本轮不包含：

- 改动 Logo、Slogan、颜色体系或唱片式层叠陈列。
- 评论、评分、关注、推荐算法等新互动能力。
- 重写产品详情、媒体上传、管理后台或数据存储架构。
- Cloudflare DNS 控制台操作；`www` 域名配置单独处理。

## 方案选择

采用渐进式修复：保留当前页面视觉和已经跑通的接口，调整流程入口、页面状态和代码边界。相比整体重构，这种方式更容易控制回归风险；相比只改文案，它能够真正消除无效入口和未登录发布的问题。

## 用户流程

### 登录

默认显示邮箱和密码登录。页面提供清楚的“注册账号”和“忘记密码”入口，不再使用“首次注册／忘记密码”合并文案。登录成功后优先返回 `next` 指定页面，否则返回首页；管理员继续进入管理后台。

### 注册

注册流程使用邮箱验证码：填写邮箱、获取验证码、验证邮箱、设置密码。首次创建账户前必须勾选协议，协议名称分别链接到对应页面并可在新页面阅读。已有账户进入注册流程时，界面提示改用登录或找回密码，不把注册和重置密码混成同一个概念。

### 找回密码

找回密码使用邮箱验证码确认身份，验证成功后设置新密码。成功后保持登录状态，并返回此前请求的页面。页面文案明确说明这是重置密码，而不是首次注册。

### 发布保护

进入 `/create` 后立即检查登录状态。未登录用户跳转到 `/login?next=/create`，不展示可填写的完整发布表单。检查期间显示简洁的加载状态；已登录用户继续看到现有发布页面，媒体和技术资料逻辑保持不变。

## 首页导航行为

- 今日精选：优先显示被设为精选的产品；如果当前没有精选数据，则使用稳定的默认顺序，不能伪装成已经人工精选。
- 热门：按喜欢、收藏、浏览、分享等现有互动指标形成可解释的排序。
- 最新：按发布时间倒序。
- 即将发布：显示状态为概念阶段或早期测试的产品；若没有结果，显示空状态。
- 分类和搜索继续叠加在当前导航结果上。

如果现有接口没有返回实现某项排序所需的字段，应扩充读取接口，但不得改变创建和媒体接口的行为。

## 页面状态和错误处理

- 首页首次取数使用骨架或“正在载入产品”，不先显示八个空位。
- 请求成功但没有产品时，显示友好的空状态；少量产品不再用大量空卡造成平台无人使用的印象。
- 首页请求失败时显示重试入口，而不是静默吞掉错误。
- 登录、注册和找回密码的错误放在对应表单内，保持用户输入。
- 发布登录检查失败时提供重试和返回首页，不无限停留在加载状态。

## 代码结构

- `app/page.tsx` 只负责挂载当前首页，不保留 `return` 后不可执行的旧实现。
- 首页产品筛选与排序集中在当前产品浏览组件中，使用明确的小函数表达各导航规则。
- 登录页可以继续使用单路由，但使用独立模式和明确入口，避免复制网络请求逻辑。
- 协议与隐私页面使用静态路由，内容先覆盖 MVP 所需的账户、公开内容、媒体、举报、数据使用和联系说明。
- 删除文件前确认没有 import、路由或文档依赖；当前正在使用的产品详情和媒体组件不做清理。

## 安全与隐私

- 保留现有同源检查、安全 Cookie、验证码有效期和单邮箱限流。
- 本轮不引入新的第三方身份或分析服务。
- 注册请求继续由服务端强制检查协议同意，不能只依赖前端复选框。
- 找回密码不得泄露邮箱是否已注册；面向用户的发送结果保持中性。

IP 级限流和 Cloudflare Turnstile 属于后续安全加固，不阻塞本轮流程整理。

## 验证标准

- 未登录用户进入 `/create` 会被带到登录页，登录后能够返回 `/create`。
- 登录、注册、忘记密码三个入口和标题彼此清楚。
- 注册流程可以打开用户协议和隐私政策。
- 首页四个导航至少产生可验证的排序、筛选或明确空状态。
- 首页加载时不闪现“等待产品”的假空状态。
- 搜索与产品类型可以和导航组合使用。
- 桌面端与窄屏下主要按钮、输入框和产品浏览均可使用。
- 代码检查通过，正式构建成功，关键公开路由可以打开。
- 现有产品详情、喜欢、收藏、分享、举报、媒体查看和账号产品管理不回归。

## 发布策略

所有改动作为一个边界清楚的功能提交完成。验证通过后再合入和部署；如果某项首页排序受现有数据限制，界面必须诚实显示空状态，不以静态假数据代替。
